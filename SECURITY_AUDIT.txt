Procedimiento SQL de solo lectura para un administrador autorizado
------------------------------------------------------------------
El esquema `public` y los nombres `alimentos`, `categorias` y `detalles_medida` se observaron en respuestas REST. Ejecutar estas consultas desde una conexión administrativa autorizada, en una transacción de solo lectura; no se han ejecutado aquí. Inventariar primero cualquier relación que el propietario clasifique como privada. Sustituir/añadir solo nombres confirmados por el administrador.

```sql
BEGIN TRANSACTION READ ONLY;

-- Estado RLS de las relaciones del catálogo observadas.
SELECT n.nspname AS schema_name,
       c.relname AS table_name,
       c.relrowsecurity AS rls_enabled,
       c.relforcerowsecurity AS rls_forced
FROM pg_class AS c
JOIN pg_namespace AS n ON n.oid = c.relnamespace
WHERE n.nspname = 'public'
  AND c.relname IN ('alimentos', 'categorias', 'detalles_medida')
  AND c.relkind IN ('r', 'p')
ORDER BY c.relname;

-- Políticas aplicables y sus condiciones de lectura/escritura.
SELECT schemaname, tablename, policyname, permissive, roles, cmd, qual, with_check
FROM pg_policies
WHERE schemaname = 'public'
  AND tablename IN ('alimentos', 'categorias', 'detalles_medida')
ORDER BY tablename, policyname;

-- Grants efectivos que Postgres calcula para los roles públicos.
SELECT table_name,
       has_table_privilege('anon', format('public.%I', table_name), 'SELECT') AS anon_select,
       has_table_privilege('anon', format('public.%I', table_name), 'INSERT') AS anon_insert,
       has_table_privilege('anon', format('public.%I', table_name), 'UPDATE') AS anon_update,
       has_table_privilege('anon', format('public.%I', table_name), 'DELETE') AS anon_delete,
       has_table_privilege('authenticated', format('public.%I', table_name), 'SELECT') AS authenticated_select,
       has_table_privilege('authenticated', format('public.%I', table_name), 'INSERT') AS authenticated_insert,
       has_table_privilege('authenticated', format('public.%I', table_name), 'UPDATE') AS authenticated_update,
       has_table_privilege('authenticated', format('public.%I', table_name), 'DELETE') AS authenticated_delete
FROM (VALUES ('alimentos'), ('categorias'), ('detalles_medida')) AS t(table_name)
ORDER BY table_name;

ROLLBACK;
```

Estas consultas inspeccionan metadatos; no reemplazan una prueba de denegación en runtime. Para verificar lecturas privadas hace falta que el propietario identifique una relación privada concreta y autorice una prueba REST mínima con el cliente público. Una prueba de escritura real queda expresamente fuera de este trabajo porque implicaría una mutación.

API de integración y smoke manual final
---------------------------------------
- `catalog.js` exporta `loadCatalog({ onStatus })` y resuelve `{ foods, fetchedAt, cached, stale, message, cacheSaved? }`. `cacheSaved` indica si la descarga reciente pudo guardarse para uso offline. `foods` son las filas REST originales, incluidas sus relaciones anidadas. `onStatus` recibe `loading`, `fresh`, `stale` o `error`, con fecha/estado y mensaje cuando corresponde. El recorrido remoto ordena por `nombre.asc,id.asc`, solicita rangos sucesivos y continúa incluso tras páginas parciales; solo guarda una lista no vacía, íntegra y con IDs/nombres válidos. Si la red falla, usa la copia IndexedDB validada y devuelve `cached: true, stale: true`; sin copia válida, muestra error accionable y rechaza.
- La copia de catálogo se guarda en IndexedDB (`mi-insulina-offline`, almacén `catalogos`, clave `alimentos`) con su `fetchedAt`. El service worker solo precarga/actualiza el shell same-origin usando solicitudes nuevas con credenciales omitidas (también para navegaciones, que pueden llevar credenciales implícitas); ignora solicitudes cross-origin y las que incluyan explícitamente `Authorization`, `apikey`, `x-api-key`, `proxy-authorization` o `cookie`. El catálogo Supabase no se guarda en Cache Storage: su copia offline es explícita en IndexedDB.
- Smoke del responsable de integración, servido por HTTPS o `localhost`: abrir online e instalar el service worker; comprobar carga completa y hora `fetchedAt`; confirmar que el shell y catálogo funcionan tras activar modo offline y recargar; verificar que la interfaz identifica el catálogo guardado como potencialmente desactualizado y conserva su antigüedad; volver online y confirmar que el evento de reconexión/reintento actualiza el catálogo/fecha sin perder la comida; probar la misma publicación bajo una ruta relativa (subdirectorio) y comprobar que el manifiesto y los iconos de 192/512 px resuelven desde esa ruta. Revisar Cache Storage para el shell same-origin e IndexedDB para el catálogo; no debe aparecer una respuesta Supabase en Cache Storage.
